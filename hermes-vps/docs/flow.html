Cross-field rules — only where blank

The portal pairs these fields. A rule fires only on a field that is blank or already being written; a saved value is left alone.

4.1.15
BPL = No → AAY = Not Applicable (9). A student who is not BPL cannot be an AAY beneficiary.
4.1.16
Social category SC / ST / OBC → EWS = No (2). A reserved-category student cannot also claim EWS.
BLOOD
Code 0 ("Unknown") is offered by the UI but rejected by the API, so it is clamped to 9.
9

POST + read-back

POST /p0/api/cy/students/{sid} — the full record, so no field is silently dropped. Read-back must confirm every submitted field.

Fill mandatory subjects 3–6

401 Mathematics · 402 Science · 404 Social Science · 612 English. The portal rejects a write that leaves these at 0.

14

Exam result valid? (1, 3, 4 only)

Field 4.2.7(a). Anything else cannot satisfy the requirement.

VALID
Write normally; previous-year values carried as saved.
INVALID
Auto rule → 4.2.5(a) = None / Not Studying
The portal then disables 4.2.6(b), 4.2.7(a)/(b), 4.2.8.
Transmit null for classPY, examResultPy, examMarksPy, attendancePy — sending 0/0/4/0 is rejected.
The portal stores sentinels 99 / 0 / 999 / 0; read-back must normalise them.
15

Facility Profile — blank-only fill

height 146–160 cm · weight 42–52 kg · distance randomly 1–3 or 3–5 km (field 4.3.6) · parent education Secondary · blank Yes/No → No. Seeded per student so re-runs are identical.

Never continue on an unconfirmed write. HTTP 200 is not proof.
